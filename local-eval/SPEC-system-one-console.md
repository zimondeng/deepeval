# 规格：本地 system_one 评估控制台

状态：根据对抗性审查修订；产品范围已确认，核心机制尚未完成实验验证。

## 1. 目标与不变量

本地单用户通过页面配置评估对象、问题和标准，启动真实评估并获得可信、可追溯的结果。使用本仓库 DeepEval 源码和第三方 Jev；保留现有命令行流程。

- 评分由 JevEval 完成，页面和后端不得复制评分公式。
- system_one 是判定引擎模式；E2E/Component 是评估范围，两者不得共用含混的 mode 字段。
- 执行完成、真实调用已验证、质量达标是三个不同事实。
- 配置、数据和问题在启动时冻结；运行中编辑只影响下一次运行。
- 未完成、取消、请求失败和模拟响应不得标记为整体通过。
- 页面、配置、预览、日志和报告不持久化凭证。

## 2. 范围与最小架构

保留模型配置、JSON/JSONL 上传与逐条编辑、新建/删除用例、导出数据、三类问题编辑、E2E、Component、目标 HTTP 配置、校验、真实连接测试、取消、日志和报告。

仅三个职责边界，不要求每项能力对应独立服务或文件：

1. UI/HTTP 接口：表单、文件导入导出、请求边界检查、状态展示。
2. 运行服务：共享配置校验、输入快照、任务生命周期、报告原子保存。
3. 评估执行器：构造测试用例，通过现有适配器和 JevEval 执行评估。

配置校验与执行逻辑供页面和新 CLI 入口共用。报告是一份事实来源；页面直接从完整报告计算摘要，不生成独立 .summary 文件。日志仅记录运行事件，不作为第二份结果库。

不引入数据库、账号系统、远程部署、多用户、多项目协作、并行调度、完整 JSONPath 或前端构建链。不为未来扩展预建接口。

## 3. 部署合同与技术验证门槛

已接受的主入口仍为 Compose 中的 ui 服务，不能静默改成宿主机 Python 启动。UI 对宿主机仅发布 127.0.0.1 端口；容器内部监听地址与宿主机发布地址分开处理。

Python 标准库后端和原生 HTML/CSS/JavaScript 为实现基线。现有 eval 服务、源码镜像及 CLI 保持兼容；新增独立 UI 运行入口，不直接复用会自动读取 .env 的配置来承载会话密钥。

实现前必须验证：

- UI 容器启动兄弟评估容器所需的 Docker 客户端、Compose、daemon 访问和权限边界。
- Windows 宿主机目录到兄弟容器的路径映射；不得把 UI 容器内路径误当成宿主机路径。
- Docker 控制权限意味着较高的宿主机权限，loopback 并不消除此风险。接口不得接收任意命令、镜像名或挂载路径。
- 唯一容器身份、退出确认、启动失败清理和 UI 重启后的任务恢复。

若 Compose UI 路径不可行，记录实测原因和宿主机后端替代方案的取舍；不得在交付时悄悄替换已接受的启动方式。

现有可执行命令：

```powershell
docker compose -f local-eval\compose.yaml build
docker compose -f local-eval\compose.yaml run --rm eval
docker compose -f local-eval\compose.yaml run --rm eval python -m evals.test_jev
```

计划新增，尚未实现或验证：

```powershell
docker compose -f local-eval\compose.yaml up ui
python -m pytest local-eval\ui\tests
```

## 4. 配置合同与能力矩阵

配置包含 schema_version=1、project、jev、evaluation、dataset、target、component。固定 evaluation.engine=system_one，evaluation.scope=e2e 或 component。未知版本、未知字段和非法类型明确报错，不静默忽略。

数值拒绝布尔值、NaN 和无穷；权重必须有限且大于零；阈值范围为 [0,1]。至少启用一个有效问题。浏览器和 API 都校验，服务端为最终边界。

| 配置项 | 页面行为与约束 | 依据或待验证事项 |
|---|---|---|
| Jev base URL、model | 可编辑；URL 不含凭证 | 现有第三方适配器 |
| Jev API Key | 会话输入、清除；不回显、不导出 | 注入机制须实验验证 |
| timeout、proxy、retry | 独立配置 Jev 与目标系统 | 不能共用隐含重试策略 |
| metric name、include_reason | 可编辑 | JevEval 参数 |
| evaluation_params | E2E 选择字段；校验每条用例存在且类型正确 | SingleTurnParams 支持范围须逐项核实 |
| threshold、strict_mode | 严格模式显示实际阈值和原生严格评分语义 | 不自行重写严格模式 |
| 问题启用、类型、文本、weight | 三类问题表单；启用后映射到稳定问题 ID | API q_N 与用户 ID 映射随报告保存 |
| Noul true/false | 原生支持；第三方兼容性验证后启用 | 当前适配器未转发这两个字段，不得静默丢弃 |
| Choice options/credit | 至少两项，credit 为 [0,1] 或 null，至少一项有分值 | null 表示不适用；credit 留在 DeepEval 侧 |
| Score levels | 2–10 个唯一、非空等级，从低到高 | 当前源码约束 |
| async_mode | 首版固定 false，串行执行 | 执行策略，不伪装为可编辑项 |
| verbose_mode | 固定 false；页面使用脱敏事件日志 | 避免原始内容泄露 |
| flaky、内部名称后缀参数 | 首版不暴露，说明不适用原因 | 不承诺全部构造函数参数都可配置 |
| dataset | JSON/JSONL 上传、表格增删改、JSONL 导出 | 新文件保存；覆盖必须明确操作 |
| target | POST、URL、非秘密 headers、JSON body 模板、输入/turns 映射、输出点号路径、超时 | 模板禁止执行代码；缺失路径失败 |
| component | Trace、节点选择、节点问题与权重 | Trace 转换和上下文实验为前置条件 |
| output | 固定宿主机 reports 目录，页面提供下载 | 不接受任意服务端文件路径 |

在实现中维护这张矩阵，以实际源码和适配器兼容性为准。任何不支持项在页面禁用并说明原因；不得显示可编辑却忽略值。

## 5. 输入与凭证边界

配置导出只含非秘密值及凭证引用，不导出 credential.configured 这类可能过期的运行状态。导入配置后重新检查当前会话是否具备所需凭证。

Jev Key、目标系统 Authorization/Cookie 和带认证的代理信息统一作为凭证处理；不得通过 headers、URL、body 模板或调试开关绕过规则。已知凭证在错误响应中被反射时也须脱敏。默认不存完整请求响应调试副本。

不能承诺通过容器环境变量注入就满足“不落盘”：Docker 管理层可能保存环境配置。候选方案为标准输入管道传递一次性凭证，由执行器内存直接传给适配器，不放命令参数、容器环境或临时文件；只有假凭证实验通过才可定案。

应用保证不主动持久化凭证，不承诺抵御管理员读取内存、操作系统交换或崩溃转储。关闭会话后释放引用，不声称能够可靠擦除 Python 内存。

现有 CLI 的 .env 行为保持兼容；不能因此声称 CLI 也满足 UI 会话凭证的生命周期约束。

本地 API 校验 Host、Origin、请求类型及会话令牌；禁止开放跨域。请求大小、用例数量和字段长度设明确上限。文件读写限制在允许目录，拒绝路径穿越和符号链接逃逸。页面通过文本节点显示模型输出，不执行导入数据中的 HTML。

## 6. 执行、取消与重试

一次只允许一个活动任务，重复启动明确拒绝。校验和凭证检查完成后生成 run_id、冻结配置及数据快照并记录内容摘要。

执行状态：queued → running → completed / failed；queued 或 running 可进入 cancelling → cancelled。无法确认容器停止时保留 cancelling 并显示错误，不能谎报 cancelled。已确认的终态不能被迟到的回调覆盖。

每个任务绑定唯一容器身份。取消停止实际容器并等待退出确认；仅终止 Compose 客户端不算取消成功。已发送的远端请求可能继续执行或计费，取消不承诺撤回远端操作。UI 重启应核对自己的任务容器及报告，不能把中断任务恢复成成功，也不能清理无关容器。

分别记录：

- execution_status：任务生命周期。
- verification_status：not_verified / partial / verified；仅真实且结构化有效的响应计入验证。
- quality_passed：true / false / null；运行完整且没有执行错误时才可得出整体结论。

每条用例/节点保留独立状态。部分完成展示局部分数和完成数量，整体分数及 quality_passed 为空。质量低分是已完成评估，不等同请求失败。全不适用的问题保留 DeepEval 原生分数，同时明确显示不适用覆盖情况。

Jev 默认最多重试两次，退避 1 秒、3 秒，覆盖连接错误、超时、429、5xx；不重试 400/401/403 和格式错误。记录尝试次数，提示超时重试可能重复计费。目标系统默认不自动重试；只有显式确认幂等性或提供经验证的幂等键方案才允许开启。取消应中断退避。

## 7. Component 与评分一致性

E2E 使用测试字段或目标系统输出。目标请求失败不得回退 fixture。

Component 对选中节点逐个评估，保留 trace_id、span_id、父子关系和问题映射。自定义上传格式不是 DeepEval Trace 的直接等价物；转换层必须通过实际 JevEval Trace 路径验证，不能把节点输入输出包装成普通 E2E 后称为原生 Trace 评估。

输入校验覆盖缺失节点、重复 ID、非法父引用及循环。上下文范围在报告中显式记录，不静默丢掉 metadata 或必要父级信息。节点必要上下文与仅输入输出两种方案用标注样本比较后决定；完整轨迹可作为对照。

问题评分、Choice 不适用逻辑、严格模式全部复用 JevEval。组件汇总仅在所有预期节点完整执行后计算，权重显式保存；取消或错误不得被其他高分掩盖。

## 8. 报告、接口与界面

完整报告原子写入 reports/run_<id>.json，包括冻结的非秘密配置、输入快照或可验证引用、版本、模型、问题映射、预期/完成数量、逐项状态、分数、confidence、reason、breakdown、usage、尝试次数、耗时及脱敏错误。源文件之后被修改不能改变已完成报告的含义。

latest.json 为可重建副本或指针，不是第二份事实来源；并发读取不能读到半份 JSON。兼容现有 jev.json/smoke.json，不用 UI 报告覆盖旧脚本文件。usage 未返回时为未知，不能当成零。

保留 health、配置读写/校验、Jev 测试、运行启动/查询/取消、日志读取和报告下载接口；数据导入编辑优先在浏览器完成，随配置或运行提交。实现时仅为真实页面需求增加接口。纯校验不触网；测试 Jev 明确触发真实调用。

单页面分区：模型、评估范围、数据集、问题、目标系统、执行、结果。可见标签、键盘操作、焦点提示、字段错误、状态播报和响应式布局为验收项。不引入远程字体或不必要动画依赖。结果以表格与问题明细为主。

## 9. 消融实验与验证门槛

下列实验目前均未执行。既有阈值探针只证明旧规格示例误接受布尔值，不代表系统验证通过。

每组固定输入、版本和故障条件，只移除一个机制。记录脚本、命令、样本、原始结果、指标及结论到 local-eval/experiments/；不得只写“测试通过”。安全措施的消融仅使用隔离环境和假凭证。

| 实验 | 完整方案 / 消融对照 | 通过条件 |
|---|---|---|
| A1 配置边界 | 有校验 / 绕过校验 | 布尔、NaN、非法权重、空问题、越界路径被拒绝且外部调用为零；对照证明测试可捕获失效 |
| A2 取消 | 停容器并确认 / 仅杀客户端 | 完整方案无本任务残留容器，确认后不再发新请求；取消终态不被迟到完成覆盖 |
| A3 完整性 | 完成数量门槛 / 仅聚合已有分数 | 注入第三条失败或取消后，整体通过与总分均为空；对照暴露误通过 |
| A4 凭证 | 候选管道注入 / 环境注入；脱敏启用 / 单独禁用 | 检查命令参数、容器 inspect、挂载文件、配置、日志、报告和浏览器存储，无假凭证明文；每次只改变一项 |
| A5 重试 | 0 次 / 有限重试 | 可恢复故障后成功且请求数不超预算；401/格式错误不重试；非幂等目标不重复调用 |
| A6 Component 上下文 | 必要上下文 / 仅输入输出，完整轨迹作参考 | 固定人工标注集，至少每样本每变体运行三次，报告准确性、归因、token 与耗时；比较前冻结可接受差异，不凭单次调用选方案 |
| A7 评分一致性 | 页面执行器 / 相同输入直接 JevEval | 固定结构化答案下逐项分数、阈值、严格模式和不适用结果一致；该测试不算真实 Jev 验证 |
| A8 本地请求保护 | 全部检查 / 每次移除一种检查 | 跨源、伪造 Host、缺失令牌请求不能修改配置或启动任务，合法页面请求正常 |

确定性机制实验必须全部通过。若消融未表现差异，说明样本未能证明机制价值，需扩大故障样本或降低结论强度；不得据此删去安全不变量。

A6 依赖真实 Jev 和标注数据。数据不足时明确记录“未验证”，不能替代为模拟质量结论。重试和上下文的效果必须同时报告正确性、耗时及调用成本，不只挑选有利指标。

## 10. 测试、规范与完成标准

Python 保持 80 列和现有 Black/Ruff 风格，复用已有模型与验证能力，避免重复 schema。边界数值检查示例应先排除 bool，再检查数值类型、有限性和范围。

- 默认测试不触网，不读取真实 .env；用假服务和固定答案测试错误路径。
- Docker 集成测试覆盖启动、挂载、取消、重启恢复和凭证注入。
- 浏览器验证配置编辑、数据增删改导入导出、请求预览、错误、真实执行与报告下载；检查键盘和 375/768/1024/桌面宽度。
- 回归现有 smoke 与 CLI；真实 Jev 单独运行，并标注 fixture/目标系统来源。
- 未通过消融门槛的核心机制不得宣布完成；未实测真实 Jev 不得标记 verified。
- 不修改 DeepEval 核心评分语义，不提交密钥，不因实现便利删减已接受功能。
