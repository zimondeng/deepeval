# Domain Docs

This repository uses a single domain context.

Before exploring domain code:

- Read the root `GLOSSARY.md`.
- Read relevant ADRs under `docs/adr/` when they exist.
- Use glossary terms in issue titles, plans, tests and implementation notes.
- Surface conflicts with existing ADRs instead of silently overriding them.

The root `GLOSSARY.md` is vocabulary only, not an implementation specification. Create ADRs sparingly for decisions that are difficult to reverse, surprising without context and based on a real trade-off.
